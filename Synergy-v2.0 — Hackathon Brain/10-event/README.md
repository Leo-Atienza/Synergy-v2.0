# 10-event — event-fact reasoning

Companion to the canonical event docs. **Facts go in `../../docs/`; thinking-about-facts goes here.**

## Canonical (source-of-truth, lives in `../../docs/`)

- [Event facts](../../docs/seneca-hackathon-context.md) — name, host, format, logistics, contact, open questions
- [Themes verbatim](../../docs/themes.md) — all 3 challenge categories
- [Timeline + ATLAS map](../../docs/timeline.md) — day-by-day schedule
- [Event YAML](../../.hackathon/event.yaml) — machine-read state

## Thinking pages (live here)

- [[sponsors-watch]] — track sponsors as they're announced; what tracks/tech each one cares about
- [[mentor-channels]] — Discord/Teams strategy, who to ask what
- [[judge-rubric-thinking]] — reverse-engineering what judges will weight; how it should shape scope

## When to add a page here

- We hear something about the event that's NOT yet a confirmed fact (rumor, mentor mention, prior-year hint)
- We need to reason about how a confirmed fact changes our strategy
- Open question gets a new piece of evidence (but isn't fully resolved)

## When to update `../../docs/` instead

Whenever something becomes a hard fact: rule, deadline, sponsor commitment, required tech, prize amount.

After updating canonical:
1. Add a note in the relevant thinking page here pointing back to the new fact ("→ confirmed in seneca-hackathon-context.md")
2. Append a row to [`../log.md`](../log.md)
3. Update [`../hot.md`](../hot.md)
